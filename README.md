# Эмулятор оболочки ОС - вариант 20

Практическая работа по конфигурационному управлению, вариант 20.

## Возможности

- графическое окно в стиле Terminal macOS;
- защищённая от ввода область истории команд;
- приглашение `vfs:~$` перед каждой командой;
- отдельное поле для ввода команды внизу окна;
- отображение вводимой команды в строке приглашения в реальном времени;
- разбор введённой строки на команду и аргументы по пробелам;
- команды-заглушки `ls` и `cd`;
- команда `exit` для завершения работы;
- сообщения об ошибках для пустого ввода, неизвестной команды и неверного
  вызова `exit`.
- параметры запуска для пути к VFS, JSON-журналу и стартовому скрипту;
- журнал вызовов команд в формате JSON;
- последовательное выполнение команд из стартового скрипта.
- загрузка выбранной директории VFS в оперативную память;
- сохранение снимка VFS командой `vfs-save <путь>`.
- полноценные команды `ls`, `cd`, `rev` и `tail` для VFS.

Если указан параметр `--vfs-path`, программа считывает всю структуру каталога
в память при старте. После этого исходная директория не изменяется. В
заголовке окна отображается имя загруженной VFS, а без параметра — `demo-vfs`.

## Запуск

Нужен Python 3 с библиотекой Tkinter. В macOS и большинстве дистрибутивов
Python она входит в стандартную поставку.

```bash
./run.sh
```

Либо:

```bash
python3 -m src.main
```

### Параметры запуска

| Параметр | Назначение |
| --- | --- |
| `--vfs-path <путь>` | Путь к исходной директории VFS. |
| `--log-path <путь>` | Путь к JSON-файлу с журналом команд. |
| `--script-path <путь>` | Путь к текстовому стартовому скрипту. |

Например:

```bash
./run.sh \
  --vfs-path examples/vfs-deep \
  --log-path logs/commands.json \
  --script-path scripts/startup_vfs_deep.txt
```

При запуске все параметры выводятся в консоль PyCharm или терминала. Если
параметр лога указан, каждое событие содержит имя команды, аргументы, имя
пользователя, дату и время, а также признак успешности выполнения.

### Стартовый скрипт

Скрипт — это UTF-8 текстовый файл с одной командой на строку. Пустые строки
пропускаются. Ошибочная команда отображает ошибку, но не останавливает
выполнение следующих строк.

Готовые примеры запуска:

```bash
./scripts/run_basic_demo.sh
./scripts/run_error_demo.sh
```

Оба скрипта проверяют все три параметра запуска. Второй дополнительно
демонстрирует обработку ошибочных строк.

### Проверка VFS

В каталоге `examples/` подготовлены три разные VFS: минимальная,
с несколькими файлами и с вложенностью не менее трёх уровней. Для них есть
отдельные сценарии запуска:

```bash
./scripts/run_vfs_minimal.sh
./scripts/run_vfs_files.sh
./scripts/run_vfs_deep.sh
```

Каждый сценарий загружает VFS, пишет JSON-журнал и запускает свой стартовый
скрипт. Результат `vfs-save` записывается в `generated-vfs/`; этот каталог
игнорируется Git. Перед повторным запуском одного и того же сценария удалите
соответствующую подпапку, например `generated-vfs/deep`, потому что команда
специально не перезаписывает существующие данные.

Для проверки всех команд, включая `exit`, используйте файл
`scripts/startup_stage3_all_commands.txt`. В нём `exit` стоит последней
строкой, поэтому окно закроется после выполнения сценария. Готовый запуск:

```bash
./scripts/run_stage3_all_commands.sh
```

### Команды четвёртого этапа

`ls` работает с обычными и объединёнными флагами `-l`, `-a`, `-h` в любом
порядке: например, `ls -lah`, `ls -ahl` и `ls -hla` дают одинаковый
расширенный вывод. Флаг `-a` показывает скрытые файлы, `-l` — права и размер,
`-h` — человекочитаемый размер при использовании `-l`.

`cd` принимает относительные пути (`cd docs`, `cd ..`) и абсолютные пути
внутри VFS (`cd /docs`). Команда не позволяет выйти выше корня VFS. После
перехода путь в приглашении меняется, например на `vfs:~/docs$`.

Для демонстрации всех режимов `ls`, `cd`, а также новых `rev` и `tail`:

```bash
./scripts/run_stage4_all_commands.sh
```

### Команды пятого этапа

`chmod <права> <путь>` изменяет права объекта только в памяти VFS. Права
можно передать как `755`, `0755` или `0o755`; новое значение видно в выводе
`ls -l` и сохраняется при `vfs-save`.

`rmdir <путь>` удаляет из VFS только пустой каталог. Нельзя удалить файл,
непустой каталог или корень VFS. Исходная папка на диске при обеих командах
не изменяется.

Для запуска сценария пятого этапа:

```bash
./scripts/run_stage5_all_commands.sh
```

## Команды

| Команда | Описание |
| --- | --- |
| `ls [-lah] [путь]` | Выводит содержимое каталога или имя файла в VFS. |
| `cd [путь]` | Переходит по относительному либо абсолютному пути VFS. |
| `rev <файл>` | Выводит символы каждой строки текстового файла наоборот. |
| `tail [-n число] <файл>` | Выводит последние 10 строк или указанное число строк. |
| `chmod <права> <путь>` | Меняет права файла или каталога только в памяти VFS. |
| `rmdir <путь>` | Удаляет пустой каталог только из памяти VFS. |
| `vfs-save <путь>` | Сохраняет снимок загруженной VFS в новый каталог. |
| `exit` | Закрывает приложение. Аргументы не принимает. |

`vfs-save` — сервисная команда третьего этапа. Она создаёт каталог по
указанному пути и восстанавливает в нём дерево и содержимое файлов из памяти.
Если VFS не была загружена, путь не указан или папка назначения уже существует,
команда выводит ошибку и ничего не изменяет.
